# ブラウザ操作と人間への引き継ぎ

ユーザーがセットアップを依頼したら、Firebaseプロジェクト・開発用サービスアカウント/鍵・Apple開発用ID/APNs鍵の作成は依頼範囲として進めます。工程ごとの不要な確認を挟まず、まず既存設定を調べます。課金契約、組織ポリシー変更、既存鍵の失効、本番公開はローカル開発セットアップに含めません。

## 利用するブラウザ

1. ユーザー指定のブラウザ接続を優先します。指定がなければ環境の対応コネクター/CLIを確認し、ログイン済みの管理コンソールには既存ユーザーブラウザを操作できる手段を使います。
2. Claude CodeではClaude in Chromeを接続します。未接続なら `claude --chrome` で起動、`/chrome` で接続・拡張・対象ブラウザを確認するよう案内します。[公式の接続手順](https://code.claude.com/docs/en/chrome)。
3. Codexでは利用可能なChrome拡張・Computer useツールを探索し、インストール済みの操作スキル/ツール説明を読んでから実行します。このリポジトリに特定バージョンのプラグイン絶対パス、Nodeの初期化コード、ツール名を固定しません。
4. 接続できない場合、必要な拡張・接続設定を具体的に一度案内してユーザー操作を待ちます。その間にローカルの依存導入・ビルド準備を進めます。手順書を渡すだけで作業を終えません。

ブラウザ操作はその提供元が定めるUI/DOM/Computer useのAPIを使います。Chromeプロフィール、Cookie、セッションDB、Keychain、保存パスワードを読み出したり、ログイン済みセッションを別プロファイルへコピーしたりしません。独自のヘッドレスブラウザでログインをやり直しません。

## ログイン待ち

GoogleまたはAppleのログイン画面が出たら、対象タブを表示したまま「このブラウザでGoogle / Appleにログインし、2FAまで完了したら知らせてください」と依頼します。パスワード、2FAコード、CAPTCHAは本人が入力します。返信後にアカウントと選択中のプロジェクト/チームを再確認して同じ工程から再開します。認証URLのコードやセッション情報を記録しません。

契約更新や支払いが必要な場合、またはブラウザ提供元のルールが人間の操作を要求する場合は、画面を開いたうえで該当ルールと止まった操作を示して本人へ引き継ぎます。承認を得るためにルールを広く解釈して通常の開発リソース作成まで止める必要はありません。本人が完了したら同じ承認を繰り返し求めません。

## ダウンロード

JSON鍵とp8は内容をブラウザで開かず、ダウンロードします。クリック時刻と対象リソースを記録し、ブラウザが返すダウンロード成果物/保存先、またはその操作で新たに生成された該当ファイルを特定します。無関係なダウンロードやホーム全体を探索しません。

取得したファイルは `chmod 600` し、[Firebase](FIREBASE.md) / [Apple](APPLE.md)の補助コマンドへパスを渡します。鍵の内容・Firebase設定・relay設定をstdoutや会話へ出しません。補助コマンドは形式を検証し、git管理外の私有ディレクトリへコピーします。

取り込み成功後、今回取得した元ファイルと取り込み先の一致をローカルで検証し、元ファイルを `.oyobidashi/` 内へ移すなどしてDownloadsに放置しません。以前からあるユーザーの鍵を削除しません。ブラウザがダウンロード成果物を提供できなければ、本人へ保存先のファイルパスだけを聞き、鍵の貼り付けは求めません。

## 再開

クラウド画面で作成済みかを確認してから作成ボタンを押します。重複プロジェクト、不要な鍵の追加、リソース上限を避けるためです。画面ラベルが変わっていたら最新の画面と公式資料から次の操作を判断し、座標や古いスクリーンショットだけに依存しません。途中で止まった工程は `.oyobidashi/setup-state.json` にリソースIDと理由を記録します。
